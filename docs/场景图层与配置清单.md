# 场景图层与配置清单

记录代码在三维场景里创建了什么、依赖哪些配置和资源。写新模块前先读 `docs/模块开发约定.md`。

## 1. 运行时配置与数据文件

| 文件 | 内容 |
|------|------|
| `public/config/dev.js` / `prod.js` | DTS Cloud 地址、工程 Id |
| `public/config/smart-city.js` | `effectsPak` 效果总包路径、`ambience` 底图风格、`cameras` 各模块默认相机位、`heatmapZ` 热力图垂直范围 |
| `public/data/smart-city/geo.json` | 地理底数据，由 `scripts/build-geo.mjs` 生成，不要手改 |
| `public/data/smart-city/overview.json` | 总览 mock：指标、热点事件、摄像头、告警（坐标为 WGS84 经纬度；片区不在这里，来自 geo.json） |
| `public/libs/*.js` | 效果总包的前端适配库，按需加载 |

`smart-city.js` 的各项：

| 配置 | 说明 |
|------|------|
| `effectsPak` | 效果总包（UE pak）在**渲染主机**上的绝对路径。留空则不挂载 |
| `ambience` | `{ tint, saturation, brightness, contrast, bloom }`，见第 3 节。缺省的项用代码里的默认值 |
| `cameras.<模块>` | 默认相机位 `[x, y, z, pitch, yaw]`（投影坐标，米）。键：`overview / traffic / security / environment / lifeline` |
| `heatmapZ` | 热力图垂直范围 `[minZ, maxZ]`（米），要覆盖场景地面高度 |

## 2. 效果总包

代码：`src/scene/effects.ts`。

- **挂载**：`mountEffectsPak()` 用 `pakFilePath` 创建一个放在地下（z = -10000）的加载器 `customObject`（id `sc_pak_loader`），渲染端随之挂载整个 pak，不需要改 Cloud 的安装目录。之后再查询这个对象的蓝图函数：能列出函数才算挂载成功。只挂载一次，结果记在 `cityBase.pak`。
- **适配库**：`public/libs` 下的脚本是挂在 `window` 上的全局对象，由 `loadLib(name)` 按需插入 `<script>` 加载，同一个库只加载一次。`flow-fx / stream-flow / spatial-flow` 依赖 `dynamic-lines`，会先加载它。

  | `loadLib` 名称 | 全局对象 | 用在 |
  |------|------|------|
  | `dynamic-lines` | `DTSDynamicLines` | 已登记，kit 目前不用（见下方 `flowLine` 的说明） |
  | `flow-fx` | `DTSFlowFX` | 同上 |
  | `region-dot-flow` | `RegionDotFlow` | `regionLayer` 点阵流光 |
  | `electronic-fence` | `ElectronicFence` | `fence` 电子围栏 |
  | `view-frustum` | `ViewFrustum` | `frustum` 摄像头视域 |
  | `stream-flow` / `spatial-flow` / `polygon-mask` / `dash-lines` | `DTSStreamFlow` / `DTSSpatialFlow` / `PolygonMask` / `DTSDashLines` | 已登记，kit 里还没有封装 |

  `public/libs/heat-column.js` 目前没有在 `effects.ts` 里登记。

- **兜底**：没配置路径、路径不对或挂载失败时 `cityBase.pak === false`，页面不报错：
  - 城市总览的片区用半透明面（`area`）代替点阵流光；
  - 经 `ModuleScene.effect()` 创建的效果如果创建失败，只在控制台告警，其它图层照常。

## 3. 底图风格（ambience）

`applyAmbience()` 在底座启动时执行一次：

- 对图层树里类型为 `EPT_Scene` 的地形/影像图层调用 `tileLayer.setStyle`：按 `tint` 染色，设置 `saturation / brightness / contrast`；
- 云量设为 0、关闭夜间模式；
- 泛光强度设为 `bloom`。

默认值 `{ tint: [0.78, 0.88, 1, 1], saturation: 0.75, brightness: 0.2, contrast: 1.1, bloom: 0.7 }`，效果是把影像压成偏冷的黄昏色调。工具栏「图层管理」里的「黄昏底图」开关调用 `setAmbienceEnabled`：关闭时把影像恢复原色（不改泛光）。

## 4. 地理数据管线

```
scripts/build-geo.mjs ──(npm run geo)──▶ public/data/smart-city/geo.json
        │                                          │
  海岸线、主干路、片区定义、地标                   ├─ getGeoData()（src/api/geo.ts，只请求一次）
  （WGS84，对着场景影像校准）                      └─ buildCityGeo(raw, project) ─▶ CityGeo（投影坐标，米）
```

- 修改海岸线、道路、片区、地标后运行 `npm run geo`（即 `node scripts/build-geo.mjs`）重新生成，再跑一遍单元测试（`src/scene/__tests__/geoData.spec.ts` 会体检生成结果）。
- geo.json 的内容：主岛海岸线 `island`、向内收 250 米的陆地范围 `land`、16 个片区、17 条道路（5 条主干路 + 12 条横街）、36 个路口（横街 × 纵向主干路）、21 个地标（含 3 座桥，桥允许落在海岸线外）。结构见 `src/types/geo.ts`。
- `CityGeo`（`src/scene/geo.ts`）是投影后的同一份数据：`districts[].ring / centerXY`、`roads[].line`、`intersections[].xy`、`landmarks[].xy`，以及 `district(id) / road(id) / landmark(id)`、`onLand(p)`、`districtAt(p)`、`landGrid(step)`。`xy(p)` 只认 geo.json 里出现过的经纬度，其它坐标会抛错。
- 折线工具：`alongLine(line, step)`、`lineLength(line)`、`pointAt(line, t)`、`sliceLine(line, from, to)`、`pointInRing(p, ring)`。
- **所有模块的 mock 数据都从 geo.json 派生**（点位用路口、地标或沿路取点，面用片区，面状分布用 `landGrid`），不手写经纬度。总览的热点、摄像头坐标写在 overview.json 里，进入场景时单独投影。

## 5. 城市底座（CityBase）

代码：`src/scene/CityBase.ts`，单例 `cityBase`。各模块进入前 `await cityBase.start()`：

1. 等场景就绪；没连上时返回 `null`（面板照常显示）；
2. 逐类清空接口对象（marker、marker3d、polygon、polygon3d、polyline、odline、beam、radiationPoint、heatmap、customObject）：场景对象存在渲染实例里，页面刷新后不会消失，先清掉上一次页面留下的；
3. `applyAmbience()`；
4. `mountEffectsPak()` → `cityBase.pak`；
5. 读取 geo.json 并一次投影完 → `cityBase.geo`（`CityGeo`）；
6. 画路网和海岸线。

`start()` 只执行一次，切换模块不重建。底座创建的对象不随模块进出而删除：

| 对象 | 类型 | id | groupId | 说明 |
|------|------|----|---------|------|
| 路网 | polyline | `sc_base_road_<道路id>` | sc_base | `plainLine` 发光实线，不依赖总包。只是城市骨架，比各模块自己的图层暗一档、细一档；主干路比其余道路更粗更亮 |
| 海岸线 | polyline | `sc_base_coast` | sc_base | 闭合细线，始终用内置样式 |
| 总包加载器 | customObject | `sc_pak_loader` | — | 不可见，仅用于挂载 pak |

`cityBase.setRoadsVisible(visible)` 显示/隐藏路网（不含海岸线）。需要自己画路况的模块进入时隐藏、离开时恢复。

## 6. 场景 kit

代码：`src/scene/kit.ts`。场景里的对象一律用这里的构造函数和配色。

配色：`COLOR`（与界面设计令牌一致）、`RAMP`（数值分级，低 → 高，前四档蓝、最高两档暖色）、`STATUS_RAMP`（畅通 → 拥堵）、`LEVEL_COLOR`（告警等级，1 级最严重）；`rgba(hex, alpha)`、`rampColor(t, ramp)`。

| 构造函数 | 对象类型 | 需要总包 | 用途 |
|------|------|------|------|
| `plainLine` | polyline | 否 | 发光实线，`flow: true` 为内置流动样式 |
| `flowLine` | polyline | 否 | 城市级俯视下的发光实线（道路、管线、路线）。`style` 只影响粗细：pulse / arrow 原宽，particles 80%，dash 60% 且略透明；最细 10 米，亮度夹在 0.8–3。`speed / spacing / reverse` 目前不起作用。`prepareFlowLines()` 是保留的空入口 |
| `ripple` | radiationPoint | 否 | 贴地扩散波纹 |
| `pin` | marker | 否 | 文字标注（深色底牌 + 牵引线），`userData` 为 `{"id": 业务id}` 的 JSON 字符串 |
| `arc` | odline | 否 | 两点间的抛物线飞线 |
| `column` | polygon3d | 否 | 六棱柱，用高度表达数值 |
| `area` | polygon | 否 | 贴地范围面：半透明填充 + 描边 |
| `circleRing` | —（顶点） | 否 | 圆环顶点，配合 `area / fence` 画圆形范围 |
| `heatmap` | heatmap | 否 | 平面热力图，值会被夹到 `range` 内 |
| `regionLayer` | 效果库对象 | 是 | 点阵流光：一组区域各一种颜色，可 `setColors` 换色 |
| `fence` | 效果库对象 | 是 | 电子围栏 |
| `frustum` | 效果库对象 | 是 | 摄像头视域 |

`regionLayer / fence / frustum` 返回 `SceneEffect`（`show / hide / remove`），在场景类里用 `this.effect(token, 图层key, () => 创建)` 登记：离开时自动删除，图层开关时跟着显示/隐藏。

## 7. 通用工具栏

组件 `SceneTools` + `BaseLayerPanel`，行为在 `src/composables/useSceneTools.ts`，五个模块共用。八个工具都可用：

| 工具 | key | 行为 |
|------|-----|------|
| 图层管理 | `layers` | 打开/关闭底图图层面板：路网流光（`cityBase.setRoadsVisible`）、黄昏底图（`setAmbienceEnabled`）、云层（云量 0.4 / 0） |
| 城市巡航 | `tour` | 按模块给的机位（至少两个，相邻机位间隔 7 秒）创建并播放相机巡航 `sc_tour`；再点一次停止；播完按钮自动弹起（SDK 没有循环播放） |
| 测量 | `measure` | 开始直线测距，在场景里依次点击；再点一次工具结束 |
| 昼夜切换 | `night` | 开/关夜间模式 |
| 天气模拟 | `rain` | 开：加厚云层并下雨；关：停雨，云量回到「云层」开关对应的值 |
| 截图 | `snapshot` | 把视频流当前帧存成 PNG（`智慧城市-日期-时间.png`）；画面没就绪时提示 |
| 视角复位 | `reset` | 停止巡航，回到本模块的默认相机位 |
| 全屏 | `fullscreen` | 进入/退出浏览器全屏 |

图层管理和全屏不依赖场景；其余工具在场景没连上时不响应。离开模块时自动停止巡航和测量。

## 8. 分辨率适配

`index.html` 头部的脚本设置根字号，样式里的 px 由 postcss-pxtorem 转成 rem（1920×1080 设计稿下 1rem = 10px）：

- 先按宽度：≥ 3840 固定 20px（2 倍），≥ 2560 固定 12.5px（1.25 倍），≤ 768 固定 7.5px，其余 `10 × 宽度 / 1920`；
- 再受高度约束：`10 × 高度 / 1080`，两者取小。窗口比 16:9 更扁时（例如带地址栏的浏览器窗口）按高度缩小，保证一屏放得下；
- 下限 5px。

JS 里的像素值走 `src/utils/viewportScale.ts`：`scalePx(px)`、`designPxToRem(value)`。图表 option 按设计稿 px 书写，`LineChart` 用 `scaleOptionSizes(option)` 换算——字号、线宽、`symbolSize`、间距等尺寸字段和 `grid` 的 `left / right / top / bottom` 乘上当前倍数，`data` 和函数（formatter）原样保留；容器尺寸变化时重算。

## 9. 各模块的场景图层

模块场景类继承 `ModuleScene`：进入时创建，离开时全部删除。图层处于隐藏状态时不创建对象，显示时才创建。

### 城市总览

代码：`src/views/overview/OverviewScene.ts`。四个图层开关默认全开。

| 图层开关 | 图层 key | 类型 | id 规则 | groupId | 说明 |
|------|------|------|---------|---------|------|
| 片区密度 | `district` | 效果库对象（有总包） | `sc_overview_districts`（整层一个对象） | — | 点阵流光，颜色按所选时刻的人口密度取 `RAMP`，时间轴变化时换色 |
| 片区密度 | `district` | polygon（没有总包） | `district-<片区id>` | sc_district | 半透明面兜底，颜色取进入时刻的密度，不随时间轴变化 |
| 人口热力 | `heat` | heatmap | `population-heat` | sc_heat | 480 米陆地网格 + 热点事件周围的人群；时间轴变化时整体替换 |
| 热点事件 | `hotspot` | marker | `hotspot-<事件id>` | sc_hotspot | 文字为「名次  简称」，按热度着色；可点击 |
| 热点事件 | `hotspot-ripple` | radiationPoint | `hotspot-ripple-<事件id>` | sc_hotspot_ripple | 波纹半径随事件活跃度变化；跟随「热点事件」开关 |
| 摄像头 | `camera` | marker | `camera-<摄像头id>` | sc_camera | 文字为摄像头编号，离线为灰色；可点击 |

点击标注：`EventDispatcher` 按 groupId 派发 `sc_hotspot` / `sc_camera` 事件，`e.data.userData` 是 `{"id": 业务id}`。

## 10. 代码依赖的 ACP 图层
