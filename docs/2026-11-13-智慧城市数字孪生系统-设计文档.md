## 1. 目标与范围

用模板工程搭建一套「智慧城市」主题的数字孪生大屏系统：DTS 三维场景做底，上层叠加业务面板，面板与场景双向联动。

**本期目标（一期）**

1. 一套可运行、可演示的大屏：5 个业务模块 + 统一框架。
2. 每个模块都有「面板 ↔ 三维场景」联动，而不是只贴图表。
3. 数据走统一接口层，一期用模拟数据，后续换真实接口时不改页面。

**不在一期范围**

- 登录/权限/后台管理（沿用模板 token 校验，不新做）。
- 真实业务系统对接、视频平台对接（预留接口，用占位流）。
- 场景建模本身（ACP 工程由场景同事提供，本文只约定图层命名）。
- 多屏联动、移动端适配。

| 视频 | `template/videoStream/`、`template/video/DhPlayer.vue` | 监控画面 |
| 现成业务样例 | `views/test2/`（事件监测）、`views/test/`（智慧园区） | 事件模块直接改造 |

模板规范里与本项目相关的硬性要求：

- 正式项目**禁止**沿用 `src/template` 的组织方式——需要的组件拷到 `src/components` 或模块目录下，`src/template` 整体不带入新工程。
- 页面放 `views/<模块>/`，组件内不直接调接口，统一走 `api/`。
- 代码控制的图层/分组名必须全局唯一，并和场景同事对齐（模板 `100-场景图层控制清单.txt` 的做法）。

## 4. 方案选择

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **A. 多模块路由 + 共享场景（推荐）** | 一个常驻 TwinPlayer，顶部导航切路由，每个模块自带面板和「场景控制器」 | 完全贴合模板 Layout/Header 结构；模块独立，可逐个交付；切模块不重连场景 | 模块切换时要严格清理场景对象 |
| B. 单页 + 图层开关 | 一个页面，左右面板固定，靠图层树勾选叠加专题 | 实现最快 | 专题一多面板就挤；专题间场景对象互相干扰；演示叙事弱 |
| C. 配置驱动低代码 | 面板、图表、场景动作全部 JSON 配置 | 后续加模块快 | 一期投入大，模板没有对应基础，过度设计 |

**选 A。** 模板本身就是这个结构（`Layout.vue` = TwinPlayer + Header + router-view），风险最低；但吸收 C 的一点：坐标、图层名、点位等**场景相关数据**放配置，不写死在代码里。

## 5. 功能设计

### 5.1 模块总览

顶部导航 5 个模块，默认进入「城市总览」。

| 模块 | 路由 | 回答的问题 |
|------|------|------------|
| 城市总览 | `/overview` | 这座城市现在整体怎么样？ |
| 智慧交通 | `/traffic` | 哪里堵、车流如何、有无事故？ |
| 公共安全 | `/security` | 监控在哪、发生了什么事件、处置到哪一步？ |
| 生态环境 | `/environment` | 空气、水质、噪声达标吗？哪里超标？ |
| 城市生命线 | `/lifeline` | 供水、电力、排水、区域供冷设施运行正常吗？ |

### 5.2 各模块内容

每个模块统一为：**左面板（态势指标）+ 右面板（明细/告警）+ 底部或右侧工具按钮 + 场景表现**。

**① 城市总览**

总览围绕「城市热点」展开（2026-11-13 按评审意见调整）：

- 左：城市体征（常住人口、在线设备、今日事件、办结率）；**人口密度峰值变化**（当前在岛人口、预计峰值及时刻、最高密度，24 小时曲线含今日实测/预测/昨日）；片区人口密度排行（含较 1 小时前变化）。
- 右：**城市热点事件** TOP5（热度、现场人数、类型、片区）；**重点摄像头** 2×2 画面；实时告警（汇总各模块）。
- 场景：片区边界；**人口热力**（随时间轴变化）；**热点事件**编号标注；**摄像头**点位。点击热点事件 → 飞到现场并弹出卡片（现场画面、热度、人数、周边摄像头数）；点击摄像头 → 弹出画面。
- 底部**时间轴**：00–24 时，可播放/拖动，联动人口热力与曲线上的当前时刻，标出预计峰值时刻。
- 图层开关：人口热力 / 热点事件 / 摄像头 / 片区边界。
- 图例：人口密度色带、热点事件、摄像头、片区边界。

**② 智慧交通**

- 左：路网拥堵指数、平均车速、在途车辆；拥堵路段 TOP10；分时车流曲线。
- 右：交通事件列表（事故/施工/管制）；路口信号灯状态；公交/地铁客流。
- 场景：主干道按拥堵等级着色的流动线（`FlowLine`/`TerrainLine`，绿黄红）；重点车辆实时轨迹（`rtlv` + 模拟定位源）；交通事件 Marker，点击弹详情并飞到现场。
- 联动：点击 TOP10 路段 → 相机飞到该路段并高亮。

**③ 公共安全**

- 在模板 `views/test2`（事件监测）基础上改造，这是模板里最成熟的现成模块。
- 左：今日事件统计、事件类型分布、各街道事件量。
- 右：事件处置流程（上报→派单→处置→办结）、部门处置效率、AI 识别告警。
- 场景：摄像头点位 Marker + 摄像头视域（`ViewFrustumFx`）；重点区域电子围栏（`ElectronicFenceFx`）；事件点位闪烁；巡逻人员实时位置。
- 联动：点击摄像头 → 弹视频窗口（一期占位视频流）；点击事件 → 详情面板 + 飞行定位 + 显示周边 500 米摄像头（turf 缓冲区计算）。

**④ 生态环境**

- 左：AQI 及六项污染物、空气质量日历/趋势；各区空气质量排行。
- 右：水质监测断面达标率、噪声监测、超标告警列表。
- 场景：监测站点 Marker（按等级着色）；各区 AQI 热力柱（`HeatColumn`）；超标区域状态标注（`ZoneMarkerFx`）；场景天气跟随数据（雾霾/晴）。
- 联动：点击站点 → 该站 24 小时曲线弹窗。

**⑤ 城市生命线**

- 左：供水、电力、排水、区域供冷四类设施的在线率与负荷；今日用量曲线。
- 右：设施告警（爆管、过载、积水、供冷异常）；巡检工单进度。
- 场景：地上建筑开启 X 光/半透明（`enableXRay`）显示地下管网；管线光流表示流向（`StreamFlow`）；告警点位闪烁；积水点「多边形漫开」表现淹没范围（`PolygonSpreadFx`）。
- 联动：点击告警 → 定位 + 高亮受影响管段 + 列出影响范围内小区。

### 5.3 通用交互

- 每个模块页固定三件套，位置一致：
  - **通用工具栏**（场景左上，竖排图标）：图层管理、城市巡航、测量、昼夜切换、天气模拟、截图、视角复位、全屏。
  - **图例**（场景左下）：说明当前页场景上的颜色和符号。
  - **图层开关**（场景右下）：当前模块的专题图层显隐。
- 顶部 Header：系统标题、模块导航、日期时间、天气。
- 面板可折叠（`CollapsiblePanel`），折叠后场景可视面积扩大。
- 场景对象点击统一由 `ClickSelectedHandler` 分发到当前模块。
- 全局告警：任何模块的高等级告警都会在总览滚动列表出现，点击跳到对应模块并定位。

## 6. 技术架构

### 6.1 分层

```
┌──────────────────────────────────────────────┐
│ views/<模块>/   页面与面板（只管展示与交互）   │
├──────────────────────────────────────────────┤
│ <模块>Scene.ts  场景控制器（只管三维表现）     │
├───────────────────────┬──────────────────────┤
│ stores/ 模块状态       │ api/ 数据接口层       │
├───────────────────────┴──────────────────────┤
│ components/dts/DtsFacade + effects + rtlv     │
├──────────────────────────────────────────────┤
│ DTS Cloud（渲染）      │ 数据源（mock / 真实） │
└──────────────────────────────────────────────┘
```

规则：面板不直接调 `DtsFacade`，只调本模块的场景控制器；场景控制器不碰 DOM、不调接口，数据由页面传入。这样面板和场景可以各自独立开发、测试。

### 6.2 目录结构（新工程 `src/`）

```
src/
├── api/
│   ├── request.ts                # axios 封装
│   ├── overview.ts  traffic.ts  security.ts  environment.ts  lifeline.ts
│   └── mock/                     # 一期模拟数据源（见第 7 节）
├── components/
│   ├── dts/                      # 模板原样带入（Facade、Player、事件）
│   ├── effects/                  # 从 template/dts/effects 拷入，只带用到的
│   ├── rtlv/  scene-player/      # 模板原样带入
│   ├── panel/                    # PanelFrame、IndicatorCard、RankList、ScrollTable 等通用面板件
│   └── chart/                    # ChartFrame + 本项目图表封装
├── scene/
│   ├── ModuleScene.ts            # 场景控制器基类：enter() / leave() / 对象登记与统一清理
│   ├── SceneConfig.ts            # 读取 gVar.smartCity，带类型
│   └── SceneLinkage.ts           # 场景点击 → 模块回调的分发
├── views/
│   ├── layout/  header/          # 模板带入并改造导航
│   ├── overview/                 # OverviewMain.vue、OverviewLeft.vue、OverviewRight.vue、
│   │                             # OverviewTools.vue、OverviewScene.ts、_components/
│   ├── traffic/  security/  environment/  lifeline/   # 同上结构
├── stores/modules/               # app、dts、user（带入）+ alarm（全局告警）
├── router/                       # index.ts + module/*.ts（每模块一个路由文件）
└── styles/ types/ utils/ i18n/   # 模板带入
```

不带入：`src/template`（按需拷组件）、`views/test`、`views/module-a/b`、`views/home` 演示页、水利相关组件、有限元相关。

### 6.3 场景控制器（核心约定）

每个模块一个 `XxxScene extends ModuleScene`：

- `enter()`：路由进入时调用——设置相机、切图层显隐、创建 Marker/特效、启动实时对象。
- `leave()`：路由离开时调用——基类按登记表统一清除本模块创建的所有对象、停止定时器和订阅。
- `update(data)`：数据刷新时更新场景表现（例如路段颜色、热力柱高度）。
- `focus(id)`：面板点击某条记录时的定位与高亮。

基类负责「登记—清理」，模块里凡是创建场景对象都通过基类方法登记，避免模块切换后残留对象（方案 A 的主要风险点）。

DTS 未连接或场景未就绪时：`enter()` 排队等到场景 OnReady 再执行；连接失败时面板照常工作，Header 显示「场景未连接」提示，不白屏。

### 6.4 场景配置化

新增 `public/config/smart-city.js`，挂到 `gVar.smartCity`，与模板 `dev.js` 同一机制，改配置不用重新打包：

- 各模块的默认相机位。
- 图层/分组名称映射（如「地上建筑」「地下管网」「道路」「行政区」）。
- 行政区边界、主干道路线、点位坐标的数据文件路径（`public/data/smart-city/*.json`）。

换场景时只改这一份配置和数据文件，代码不动（对应假设 A1）。同时在新工程维护一份《场景图层控制清单》，写明代码依赖的图层名，交给场景同事对齐。

## 7. 数据设计

### 7.1 接口层

`api/<模块>.ts` 每个函数返回带类型的 Promise，页面只认这一层。通过环境变量 `VITE_DATA_SOURCE = mock | http` 切换实现：

- `mock`：读 `public/data/smart-city/*.json`，并由 `api/mock/` 做定时小幅扰动，模拟实时变化。
- `http`：走 axios 请求真实后端（一期只留函数壳和类型，不实现）。

> 模板 README 说明 Mock 应使用独立的 MockServer 工程。如果你们有 MockServer，这里可以改为直接请求它，`api/mock/` 就不需要了——见第 11 节待确认项。

### 7.2 实时数据

- 车辆、巡逻人员位置：复用 `rtlv/DispatchCenter`，新增一个 `MockLocationParser`，沿配置的道路路线回放轨迹；接真实数据时换成模板已有的 WebSocket/MQTT 解析器。
- 告警：`stores/modules/alarm.ts` 统一存放，mock 模式下定时随机产生，各模块订阅。
- 指标类数据：按模块定时轮询（默认 30 秒），离开模块时停止。

### 7.3 主要数据对象

| 对象 | 关键字段 |
|------|----------|
| 行政区 District | id、名称、边界坐标、各领域指数 |
| 告警 Alarm | id、所属模块、等级、标题、坐标、时间、状态 |
| 路段 RoadSegment | id、名称、路线坐标、拥堵等级、车速 |
| 事件 CityEvent | id、类型、街道、坐标、处置阶段、责任部门 |
| 摄像头 Camera | id、名称、坐标、朝向/视场角、视频流地址 |
| 监测站 Station | id、类型（空气/水/噪声）、坐标、最新指标、等级 |
| 设施 Facility | id、类别（供水/电力/排水/供冷）、坐标、状态、负荷 |
| 管段 Pipe | id、类别、路线坐标、流向、状态 |

坐标统一用场景投影坐标（与模板 `dev.js` 示例一致）；如数据源是经纬度，用模板已有的 `DtsConverter`/proj4 在 api 层转换，页面和场景层只见投影坐标。

## 9. 异常处理

| 场景 | 处理 |
|------|------|
| DTS Cloud 连不上 | 面板正常显示，Header 提示场景未连接，提供重连按钮 |
| 特效 PAK 未部署到渲染机 | 该特效跳过并在控制台明确报出缺哪个 PAK，其余表现不受影响 |
| 配置的图层名在场景中不存在 | 启动时做一次图层名校验，缺失项汇总提示，不中断 |
| 接口失败/数据为空 | 面板显示空状态，保留上次数据，不弹阻断式报错 |
| 模块快速切换 | `enter()` 未完成时 `leave()` 也能正确清理（基类用代次号丢弃过期回调） |
