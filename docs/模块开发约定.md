# 模块开发约定

五个业务模块（城市总览、智慧交通、公共安全、生态环境、城市生命线）共用一套框架。新模块照着城市总览（`src/views/overview/`）写。

## 1. 先读这些文件

| 文件 | 内容 |
|---|---|
| `src/views/overview/OverviewMain.vue`、`OverviewScene.ts`、`OverviewLeft.vue`、`OverviewRight.vue` | 参考实现：页面骨架、场景图层、左右面板 |
| `src/scene/kit.ts` | **场景配色和所有图层对象的构造函数**。场景里的东西一律用它，不要自己拼 DTS 参数、不要自定颜色 |
| `src/scene/geo.ts`、`src/types/geo.ts` | 投影后的地理数据 `CityGeo`：片区、道路、路口、地标、陆地范围，及折线工具（`alongLine / pointAt / sliceLine`） |
| `src/scene/ModuleScene.ts` | 场景控制器基类：`add / replaceLayer / effect / setLayerVisible / leave` |
| `src/scene/CityBase.ts` | 城市底座（底图风格、效果总包、路网流光），`cityBase.start()` 返回 `CityGeo` |
| `src/composables/useSceneTools.ts` | 通用工具栏的行为 |
| `src/components/panel/*`、`src/components/chart/LineChart.vue` | 面板通用件：`PanelCard / StatItem / BarRow / LevelTag / SceneLegend / LayerToggle / SceneTools / BaseLayerPanel` |
| `src/styles/variables.scss` | 设计令牌（自动注入，`<style lang="scss">` 里直接用 `$accent` 等；写 px，构建时转 rem） |
| `public/data/smart-city/geo.json` | 地理底数据（真实的阿布扎比主岛：16 个片区、17 条道路、36 个路口、21 个地标） |
| `docs/DTS效果接口速查.md` | DTS 接口速查，只有 kit 里没有的东西才需要查 |

## 2. 数据必须落在真实地理上

所有 mock 数据都从 `geo.json` 派生：

- 点位用路口（`geo.intersections`）、地标（`geo.landmarks`）或沿道路取点（`alongLine(road.line, 间距)`、`pointAt(road.line, 比例)`）；
- 线用道路（`geo.roads`）或道路的一段（`sliceLine(road.line, 起, 止)`）；
- 面用片区（`geo.districts`）或以地标为圆心的圆（`circleRing`）；
- 面状分布（热力、柱阵）用 `geo.landGrid(间距)`，它只返回陆地上的点。

**不要手写经纬度**，不要用随机坐标：随机点会掉进海里，也对不上路网。需要随机性时用以 id/坐标为种子的确定性伪随机（见 `src/api/mock/population.ts` 的 `noise`），保证每次打开数据一样、测试可重复。

名称用 geo.json 里的真实道路名、片区名、地标名（如「阿拉伯湾街与哈扎·本·扎耶德街口」）。

## 3. 场景视觉规范

- 颜色只用 `kit.ts` 的 `COLOR / RAMP / STATUS_RAMP / LEVEL_COLOR`。冷色（蓝）表示常态和结构，暖色只给需要注意的东西。一个画面里暖色对象不超过总量的两成。
- 线宽按城市级俯视给：主干 60–90 米，次要 30–50 米；波纹半径 250–800 米；标注一屏不超过 30 个，多了分层或只标重点。
- 默认打开的图层不超过 4 个，其余在图层开关里默认关闭。图层之间不要大面积互相遮盖（例如片区点阵流光和热力图不要都默认开）。
- 线统一用 `flowLine`（实心发光线，不依赖效果总包）。效果总包可用（`cityBase.pak === true`）时用 `regionLayer / fence / frustum`；不可用时用 `area` 兜底，页面不能报错。
- 默认机位读 `gVar.smartCity.cameras.<模块>`（`public/config/smart-city.js`），进入时 `api.setCamera(view)`。
- 标注可点击：`pin` 的 `groupId` 用 `sc_<模块>_<类别>`，点击后 `emitter` 会派发同名事件，`e.data.userData` 是 `{"id": 业务id}` 的 JSON 字符串（见 OverviewMain 的 `onHotspotClick`）。

## 4. 页面骨架

每个模块的 `XxxMain.vue`：

- 左面板、右面板（各宽 `$panel-width`，绝对定位，见 OverviewLeft / OverviewRight 的样式）；
- 左上通用工具栏 `SceneTools` + `BaseLayerPanel`（用 `useSceneTools`，传入本模块的复位和巡航机位）；
- 底部左侧图例 `SceneLegend`（**图例必须和场景里实际的颜色、对象一一对应**），底部右侧图层开关 `LayerToggle`；
- 有时间维度的模块在底部放时间轴（可直接用 `src/views/overview/_components/TimeAxis.vue`）；
- 点击列表项或场景标注时，相机飞过去，并在右面板左侧弹出详情卡片（参考 `HotspotCard.vue`）；
- 面板内容要充实：每侧 3 张卡片，包含指标数字、一张图表、一个可点击的列表。图表用 `LineChart`（option 按设计稿 px 写，组件会自动按分辨率换算）。
- 场景没连上（`cityBase.start()` 返回 null）时面板照常显示，不报错。

生命周期照 OverviewMain：`onMounted` 里加载数据 → `cityBase.start()` → `new XxxScene(new DtsSceneApi(), geo, {...})` → 同步图层开关状态 → `scene.enter()`；`onBeforeUnmount` 里 `scene.leave()`。

## 5. 文件归属

一个模块只动自己的文件：

```
src/views/<模块>/           页面、场景类、_components、__tests__
src/api/<模块>.ts           数据入口（一期返回 mock）
src/api/mock/<模块>.ts      mock 生成（纯函数，输入 GeoData，输出本模块数据）
src/types/<模块>.ts         类型
```

共享文件（`src/scene/*`、`src/components/*`、`src/composables/*`、`src/styles/*`、`src/router/*`、`src/stores/*`、`public/config/*`、`package.json`）不要改。确实需要改时，在交付说明里写清楚要改什么、为什么。

## 6. 代码与测试

- TypeScript，不用 `any`（`__xapi`、`gVar`、`emitter` 事件参数除外）；公开函数写一行中文注释说明用途。
- mock 生成函数和场景类要有 vitest 单元测试：场景类用假的 `SceneApi`（记录 add/remove 调用）验证各图层创建了什么、离开后是否清干净、图层开关是否生效。假 `CityGeo` 可以用 `buildCityGeo(geoJson, async ll => ll.map(p => [p[0] * 1e5, p[1] * 1e5, 0]))` 构造（读取 `public/data/smart-city/geo.json`）。
- 用效果库的图层（`regionLayer / fence / frustum`）在测试里按 `pak: false` 走兜底分支，不测效果库本身。
- 完成前运行并通过：`npx vitest run src/views/<模块> src/api`、`npm run type-check`。
- 不要提交 git，不要启动开发服务器，不要打开浏览器（渲染实例只有一个，由主会话统一联调）。
